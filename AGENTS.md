# ProdFlow — Agent Instructions

## Overview

**ProdFlow** — _CIDEQ Production Management System_. SPFx web part for managing the full
make-to-order fabrication lifecycle of the CIDEQ project (Oceaneering Brazil, client Petrobras).
One traceable ID per product: **FID — Fabrication ID** (`FID0000001`).

**Stack:** SPFx **1.23** (Heft toolchain) · React **17.0.1** (SPFx ceiling) · TypeScript **5.8** ·
Node **22 LTS** · **Fluent UI React v9 (Fluent 2)** + SCSS Modules · **Zustand** (client-state) ·
**TanStack Query v4** (server-state) · **PnPjs v3** · **Zod** (validation) · **Nivo** (charts) ·
HashRouter. Primary language **pt-BR** (en secondary). Tenant: Oceaneering.

> Two phases under one FID: **Phase 1 — Budgeting** (the critical phase) and **Phase 2 —
> Fabrication & Assembly** (mostly status tracking). See `PRODFLOW-PROJECT-PLAN.md` for the full spec.

## Build & Serve

SPFx **1.23 uses the Heft toolchain (not gulp)**. Use the npm scripts generated by the scaffold:

```bash
npm install --legacy-peer-deps   # SPFx peer-dependency conflicts
npm run build                     # Heft build (dev)
npm run build -- --production     # Production bundle
npm run serve                     # Local workbench (hosted workbench is deprecated — prefer the SPFx Debug Toolbar)
npm run clean                     # Clean lib/ and temp/
npm run test                      # Jest + React Testing Library
```

- Node requirement: **>=22 <23**. Install React exactly: `npm install react@17.0.1 react-dom@17.0.1 --save-exact`.
- Dependencies are pulled from **`jfrog.oceaneering.com`** (internal policy).
- Always verify chart / heavy-type work with `npm run build` — the editor's TS server can hide SPFx build errors.

## Domain Model (essentials)

- **One list `prodflow-requests`, one item per FID**, full JSON in a `jsondata` column (header +
  nested sub-items + budget + financials + history). ~5 indexed columns promoted for query:
  `FID`, `OS`, `Phase`, `Status`, `Year`. Boards/Gantt/dashboards expand sub-items **in memory**.
- **Sub-items = BOM lines (PNs)**; they do **not** get their own FID/OF. BOM is multi-level, imported
  from the PLM (Windchill) CSV/XLSX. Modeled as a **flat list with `level` + `parentId`** (stack-by-level
  algorithm in `bomParser`); the tree is **derived in memory**; rollups aggregate **bottom-up**.
- Each BOM line gets a **mandatory make/buy strategy** (locked dropdown: `Buy·RawMaterial`,
  `Buy·CommercialItem`, `Make·InHouse`, `Make·Subcon`) decided by **Planning (PCP)**.
- Key models: `IFabricationRequest`, `ISubItem`, `IBudget`, `IFinancials`, `IDelineation`, `IQuotation`.

## Key Conventions

### Component Pair (SCSS Modules)

Every component/page has `Name.tsx` + `Name.module.scss`. SPFx 1.23 uses **css-loader**: import styles
directly (`import styles from './Name.module.scss'`) and reference classes as `styles.className`. Class
names are hashed at build and the `styles` typing is ambient (provided by the Heft rig), so there is
**no hand-written `.module.scss.ts` shim** (that was the SPFx ≤ 1.21 pattern).

### Services — Stateless Static

```typescript
export class XxxService {
  public static async getAll(): Promise<IXxx[]> {
    const items = await SPService.sp.web.lists
      .getByTitle(SP_CONFIG.lists.xxx)
      .items();
    return items.map(mapFromSP);
  }
}
```

All methods `public static`; SharePoint via `SPService.sp`; list names from `config/SP_CONFIG`
(**never hardcode**); complex data as a JSON blob column (parse on read, stringify on write).

### State Split — Zustand × TanStack Query

- **Zustand = client/UI state only** (theme, sidebar, selected FID, filters, toasts). **No fetching.**
  Pattern: `create<State>((set, get) => ({...}))`, no heavy middleware.
- **TanStack Query v4 = server-state** — the **only** door to remote data. Query hooks in `api/`
  wrap the services and provide cache/refetch/dedupe/retry + **mutations with optimistic update +
  rollback + `invalidateQueries`**. Never call SharePoint directly from a component.
- **v4, not v5** (v5 requires React 18; SPFx runs React 17).

### Concurrency (critical)

Many teams edit the **same** FID JSON simultaneously (Purchasing × Workshop × Quality). Two cooperating
layers: on the client, TanStack Query does optimistic update + rollback + `invalidateQueries`; on the
server, `RequestService` does **merge per section/sub-item + ETag/retry** — updating only the changed
subsection, **never overwriting the whole JSON**. The FID counter is atomic (ETag + retry).

### Routing & Theming

- HashRouter (SharePoint compatibility). Routes/nav from `config/ROUTES` + `config/NAV_GROUPS`.
  Dedicated page per FID: `/fid/:fid` (tabbed), never a modal.
- **Light mode is the default** (Oceaneering clean/minimal identity); dark mode available and must
  stay legible. Per-user preference persisted (`themePreference`) via `useUIStore`.
- Root classes `.prodflowLight` / `.prodflowDark`; all colors are CSS custom properties scoped under
  the app root. **Never hardcode a hex** — use `var(--...)`; status/phase colors via `useStatusColors()`.

## Critical Rules

1. **NO mock data.** All data comes from SharePoint via the `services/`, surfaced through the `api/`
   TanStack Query hooks and Zustand stores. Never hardcode or import mock datasets into UI.
2. **Reuse before creating.** Check `models/` (types), `config/` (constants incl. `SP_CONFIG`,
   `CONTRACT_WEIGHTS`, `BR_HOLIDAYS`), `services/`, `api/`, `stores/`, `hooks/`, `utils/`, and
   `styles/themes/` before declaring anything inline. Do not re-declare existing interfaces,
   duplicate CSS hex, or inline status/phase logic.
3. **Never overwrite the whole FID JSON** — merge per section/sub-item with ETag (see Concurrency).
4. **Contract weights are constants in code** (`config/CONTRACT_WEIGHTS`), not a list. In the budget
   mask only `QTD` / `HH` are editable; `Peso` is fixed; `Peso Total` / `Valor` are computed.
5. **Business-day math must include Brazilian holidays** (`config/BR_HOLIDAYS` via `utils/businessDays`).
6. **Validate at boundaries with Zod** (`schemas/`) — FID read/write and BOM import.
7. **Commits** follow `^(build|chore|ci|docs|feat|fix|perf|refactor|revert|style|test): ...`.
